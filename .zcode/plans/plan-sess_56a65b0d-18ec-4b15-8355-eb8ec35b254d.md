## Plan: `align_from_known_c2w` — c2w-derived alignment + local refinement

Add a new function to `multiview_refine/alignment.py` that computes a similarity transform `(scale, R, t)` directly from the known init-view camera extrinsic, then runs a **small local search** to correct any canonical-orientation offset. Wire it into `refine.py` as the preferred path when an init camera is available (which it always is), with fallback to the existing full search.

### New function in `multiview_refine/alignment.py`

```python
def align_from_known_c2w(
    tripo_gaussian,
    init_camera: Camera,
    cameras: list[Camera],
    rmbg_fn=None,
    scene_centroid: torch.Tensor | None = None,
    local_yaw_window: float = math.pi / 4,    # ±45°
    local_pitch_window: float = math.pi / 6,  # ±30°
    local_roll_window: float = math.pi / 6,   # ±30°
    n_rotation_samples: int = 7,
    n_scale_samples: int = 5,
    scale_range: tuple[float, float] = (0.05, 2.0),
    alpha_threshold: float = 0.1,
    verbose: bool = True,
) -> tuple[float, torch.Tensor, torch.Tensor]:
```

**Returns:** `(scale, R, t)` — same format as `estimate_similarity_transform_multiview` (`scale: float`, `R: (3,3) tensor`, `t: (3,) tensor`), compatible with `RefineableGaussians.from_tripo_splat`.

**Algorithm:**

1. **Extract tensors** from `tripo_gaussian` via existing `_tripo_gaussian_to_tensors(tripo_gaussian, device)`.

2. **Derive initial R from c2w:**
   - `R_init = init_camera.c2w[:3, :3]` (OpenCV convention — the rotation that maps canonical camera axes to world axes). Since TripoSplat's canonical camera is identity (object at origin, camera looks along +Z), rotating by `R_c2w_init` aligns the canonical "front" to the real camera's viewing direction in the scene.
   - Convert `R_init` to Euler `(yaw0, pitch0, roll0)` for the local search center. Use a decomposition: extract yaw/pitch/roll from `R_init` (ZYX intrinsic = XYZ extrinsic, matching `_euler_to_matrix`). This is a standard extraction; I'll implement a small `_matrix_to_euler_zyx(R)` helper or derive yaw/pitch/roll directly from the matrix elements.

3. **Derive initial scale:**
   - `tripo_extent = (means.max(0) - means.min(0)).norm()` — bounding-box diagonal of the Gaussians.
   - `scene_extent = compute_cameras_extent(cameras)` (existing function, max pairwise camera distance × 1.1) — or use point-cloud extent if available. `scale_init = scene_extent / tripo_extent.clamp(min=1e-6)`, clamped to `scale_range`.

4. **Derive initial translation:**
   - `tripo_centroid = means.mean(0)`.
   - `scene_centroid = scene_centroid arg or torch.zeros(3)` (object at origin in this dataset; pass point-cloud centroid if available for generality).
   - `t_init = scene_centroid - scale_init * (R_init @ tripo_centroid)`.

5. **Local refinement search** (reuses the existing render-and-compare-IoU machinery):
   - Extract real foreground masks via existing `_get_real_masks(cameras, rmbg_fn)`.
   - Search yaw in `[yaw0 - local_yaw_window, yaw0 + local_yaw_window]`, pitch in `[pitch0 - local_pitch_window, pitch0 + local_pitch_window]`, roll in `[roll0 - local_roll_window, roll0 + local_roll_window]`, scale in a narrow band around `scale_init` (±30%).
   - For each candidate, build `R = _euler_to_matrix(pitch, yaw, roll)`, apply `_apply_transform(means, scales, quats, s, R, t_init)`, render silhouettes via `_render_silhouettes` on a camera subset, compute IoU via `_compute_iou_batch`. Track the best.
   - `n_rotation_samples=7` per axis, `n_scale_samples=5` → 7×7×7×5 = 1715 candidates (subset cameras every 3rd → ~21 renders per candidate would be 36k renders — too many). **Optimization:** Phase 1 search yaw+scale only (7×5=35 candidates, pitch=roll=0), then Phase 2 fine search pitch+roll around best yaw (5×5=25 candidates). Total ~60 candidates × ~21 renders ≈ 1260 renders — fast (~10-20s vs current full search ~minutes).

6. **Final translation:** re-estimate `t` via existing `_estimate_translation(means_final, cameras, real_masks)`.

7. **Return** `(best_scale, R_best, t_best)`.

**Fallback:** if `init_camera` is `None` or c2w derivation fails, the function falls back to calling `estimate_similarity_transform_multiview` (full 360° search). This preserves the existing behavior as a safety net.

### Helper: `_matrix_to_euler_zyx(R)`
A small function (~15 LOC) to extract `(roll, pitch, yaw)` from a 3×3 rotation matrix (ZYX intrinsic / XYZ extrinsic decomposition, matching `_euler_to_matrix`'s `Rz @ Ry @ Rx`). Uses `atan2` with the standard formulas. Added to `alignment.py`.
