## Plan: PyQt5 + QtWebEngine desktop viewer (no port needed)

Create a Python desktop app that embeds the existing `cam_viewer.html` in a QtWebEngine window, loading it via `file://` so no HTTP server or port is needed. The splat and camera data are loaded from local files.

### New file
`run_cam_viewer.py` — a standalone PyQt5 script (in the project root, alongside `run_example.py` / `run_gradio.py`).

### New dependency
`PyQtWebEngine` (not currently installed). The script will print a helpful install message if missing:
```
pip install PyQtWebEngine
```
(PyQt5 5.15.10 is already installed; only the WebEngine component is missing.)

### Script behavior (`run_cam_viewer.py`)
1. Create a `QApplication` + `QMainWindow` with a `QWebEngineView` as the central widget.
2. Resolve the HTML path: `Path(__file__).parent / "static" / "cam_viewer" / "cam_viewer.html"` → convert to a `file://` URL via `QUrl.fromLocalFile()`.
3. Build the URL with **hash-fragment** params (more reliable than query strings under `file://`):
   - `#base=<relative-or-absolute-mvs-folder-path>` — defaults to `../000000/mvs/` relative to the HTML if omitted.
   - `#splat=<relative-or-absolute-splat-file-path>` — optional; defaults to `../000000/splat.ply` if that file exists, else no splat.
4. Support **CLI args** for flexibility:
   - `--base <path>` — mvs folder (absolute or relative to HTML). Default: `../000000/mvs/`.
   - `--splat <path>` — splat file path. Default: `../000000/splat.ply` if it exists, else `None`.
5. Load the URL into the WebEngineView. Set window title "TripoSplat Camera Viewer", default size 1400×900.
6. Enable WebGL in QtWebEngine settings (required for Three.js): `settings.setAttribute(WebEngineSettings.WebGLEnabled, True)` and `LocalContentCanAccessFileUrls = True` so the page can fetch local `file://` resources (JSON, PLY, PNG, splat).
7. Run the Qt event loop.

Example usage:
```bash
python run_cam_viewer.py                              # defaults: ../000000/mvs/ + ../000000/splat.ply
python run_cam_viewer.py --splat ../gradio_outputs/abc/splat.ply
python run_cam_viewer.py --base /path/to/other/mvs/
```

### `cam_viewer.html` change (small, for `file://` compatibility)
Update the params-reading block (lines ~155-167) to also read from `location.hash` as a fallback when `location.search` is empty. This makes `file://.../cam_viewer.html#splat=../000000/splat.ply` work reliably (some engines strip query strings from `file://` URLs but always preserve hash fragments). The logic:
```js
const params = new URLSearchParams(location.search || location.hash.replace(/^#/, ''));
```
This is a one-line change; existing `?base=&splat=` query-string usage (HTTP server mode) continues to work unchanged.

### Files changed
- **New**: `run_cam_viewer.py` (~60-80 LOC)
- **Edit**: `static/cam_viewer/cam_viewer.html` — one-line params fallback to read hash fragment.

### Out of scope
- No changes to `triposplat.py`, `run_example.py`, `run_gradio.py`.
- No packaging/building (no .exe). It's a `python run_cam_viewer.py` script.
- The existing HTTP-server usage of `cam_viewer.html` remains fully supported.

### Risks / notes
- Requires `pip install PyQtWebEngine` (one-time, ~100MB on Windows). Script detects missing module and prints install instructions.
- Requires internet for the Three.js/Spark.js CDN imports (same as the browser version). Could later vendor these locally if offline use is needed — out of scope.
- QtWebEngine is Chromium-based, so WebGL + ES modules + importmap all work the same as in a normal browser.
